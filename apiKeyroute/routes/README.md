# Routes Structure

این پروژه دارای ساختار مسیریابی بهینه‌شده‌ای است که برای نگه‌داری بهتر و خوانایی بالاتر طراحی شده است.

## ساختار فایل‌ها

### فایل اصلی

- **`api.php`** - نقطه ورود اصلی که تمام فایل‌های مسیر را import می‌کند

### فایل‌های مسیر (دایرکتوری `api/`)

#### 1. **`auth.php`** - مسیرهای احراز هویت

مسیرهای مربوط به:

- ورود و خروج (`sign-in`)
- فراموشی رمز عبور (`forgot/otp`, `forgot/submit`)
- اتصال شاخه‌ها (`connect/branch`, `connect/otp`)
- مدیریت توکن‌ها (`access-token`)

#### 2. **`public.php`** - مسیرهای عمومی

مسیرهای قابل دسترس بدون احراز هویت:

- لینک‌های کوتاه عمومی
- تنظیمات پایه (`config`)
- تست ارتباطات

#### 3. **`v2_panel.php`** - مسیرهای پنل مدیریت V2

شامل تمامی مسیرهای پنل اصلی:

- مدیریت کاربران و اپراتورها
- سفارشات و معاملات (`trades`)
- همکاران (`colleagues`)
- سرویس‌های آنلاین (`online`)
- ارتباط با Asterisk AMI
- آپلود فایل‌ها (S3)
- پرسنل و حضور و غیاب
- پشتیبانی (`support`)
- آکادمی
- ایمیل
- ماژول‌های اضافی
- مقالات و محتوا
- اقامتگاه‌ها
- نظرات
- درخواست‌های سفر
- Scrumboard
- مخاطبین
- هوش مصنوعی (AI)
- هسته اصلی (`core`)

#### 4. **`v2_accounting.php`** - مسیرهای حسابداری V2

تمام مسیرهای مربوط به سیستم حسابداری:

- اسناد مالی (`financial documents`)
- بدهی و بستانکار (`credit-debit`)
- حساب‌های بانکی و کیف پول
- درگاه پرداخت
- چک‌ها
- اعلامیه‌ها (`announcements`)
- سطوح حسابداری (`levels`)
- تاریخچه حساب (`account-history`)
- حسابداری Redis
- پردازش دسته‌ای (`batch accounting`)

#### 5. **`v2_charter_cartable.php`** - مسیرهای چارتر و کارتابل

ماژول‌های چارتر، کارتابل و هاب:

- مدیریت چارترها
- رزروها
- اتاق‌های اقامتگاه
- محاسبات مالی چارتر
- کارتابل (workflow) - نسخه قدیم و جدید
- سیستم نامه‌نگاری
- مدیریت گردش کار
- فیلتر اسپم
- سازمان‌ها
- هاب (Hub)

#### 6. **`b2c_v1.php`** - API مشتریان (B2C)

مسیرهای عمومی برای مشتریان:

- احراز هویت مشتری
- پروفایل کاربری
- چارتر (نسخه مشتری)
- کارت‌های اعتباری
- آپلود فایل
- معاملات
- سرویس‌های آنلاین
- مالی و کیف پول
- مسافران
- درگاه پرداخت و تخفیف
- مقالات
- درخواست‌های سفر
- لینک‌های کوتاه

## مزایای این ساختار

### 1. **نگه‌داری آسان‌تر**

- هر فایل مسئولیت مشخصی دارد
- کد مربوط به هر بخش در یک فایل مجزا است
- تغییرات محدود به یک فایل می‌شوند

### 2. **خوانایی بهتر**

- فایل اصلی `api.php` فقط ۳۵ خط است
- ساختار واضح و قابل فهم
- کامنت‌های مفید

### 3. **کار تیمی راحت‌تر**

- تیم‌های مختلف می‌توانند روی فایل‌های جدا کار کنند
- کاهش conflict در Git
- مسئولیت‌های مشخص

### 4. **بارگذاری بهینه**

- Laravel فقط فایل‌های مورد نیاز را بارگذاری می‌کند
- عملکرد بهتر

### 5. **توسعه‌پذیری**

- اضافه کردن نسخه‌های جدید API آسان است
- می‌توان فایل‌های جدید اضافه کرد بدون تغییر فایل‌های قدیمی

## نحوه استفاده

### افزودن مسیر جدید

1. مسیر را در فایل مناسب در دایرکتوری `routes/api/` اضافه کنید
2. اگر نیاز به دسته‌بندی جدید است، فایل جدید بسازید:

```php
<?php

use Illuminate\Support\Facades\Route;

Route::group(['middleware' => ['domainAccess', 'ipTrust', 'authWithJwt'], 'prefix' => 'v2'], function () {
    // مسیرهای جدید
});
```

3. فایل جدید را در `api.php` import کنید:

```php
require __DIR__ . '/api/your_new_file.php';
```

## نکات مهم

- **همیشه از middleware مناسب استفاده کنید** (`authWithJwt`, `authGuest`, etc.)
- **prefix ها را رعایت کنید** (v2, b2c/v1)
- **از نام‌گذاری یکنواخت استفاده کنید**
- **کامنت‌ها را به‌روز نگه دارید**

## Migration از نسخه قدیم

تمام مسیرها از فایل قدیمی `api.php` به فایل‌های جدید منتقل شده‌اند. API شما بدون تغییر کار می‌کند.

اگر مسیری کار نمی‌کند، احتمالاً در فایل مناسب قرار نگرفته. لطفاً بررسی کنید:

1. Controller import شده؟
2. Middleware صحیح است؟
3. Prefix درست است؟
